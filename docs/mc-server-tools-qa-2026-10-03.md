## 本轮发现并修复 / 处理

1. JAR 文件 / 目录含平台类路径分隔符会导致 Java 找不到主类。生成器已拒绝相应分隔符并解释替代目录。
2. 无害 JAR 的测试用 Java 别名重跑时复用旧 JDK，导致独立 java.home 断言失败。按真实 Java 路径隔离 fixture；没有删除 JDK 或降低断言。
3. 极高 ActiveProcessorCount 引发 GC 原生内存增加。参数认可与硬件压力分别核实，界面新增明确用途和资源风险说明。
4. 手机右下返回按钮遮挡报告数值。小屏图标改放顶部导航栏并核实层级和点击。
5. 可选数字输入 `1e` 时浏览器产生 `validity.badInput=true`，但 value 为空，原问卷会将其当未知继续计算。用单独 badInput 校验拦截；真实 DOM 验证定位字段、清空恢复、示例重置和报告停用。
6. 开服内存输入不完整后切换单位，再清空，React 数值跟踪可能不触发 change 事件而残留错误。同步原生 input 事件，真实页面复核切单位保持拦截、完全清空恢复。
7. CMD 存在同名 `ERRORLEVEL=0` 环境变量时，生成脚本原先错报实际 Java 退出码。仅在 setlocal 内清除同名覆盖，父环境不变；新增真实脚本退出码 7 回归通过。
8. 零模组、零插件的原版服此前忽略额外脚本负载。现为数据包、命令方块负载单独预算 CPU 与堆，系数在报告公开。
9. 超大预生成地图、多维度或极高网络预算此前未降级适用范围。统一规模谓词及具体提醒，4 TiB / 16 维度 / 1 Gbps 为本站提示阈值，不是官方服务器上限；不拒绝合法输入或改变原预算。
